# Project Rules Example

Fictional practice project: Reading Notes. This illustrates filled guidance; it is not a claim about a shipped app.

Purpose: Help a reader save personal book notes locally using dummy data.
Scope: Add an empty-state message. Preserve the existing list design.
Must keep working: Add, edit, delete, and refresh persistence.
Plan: Locate the existing notes component and propose a minimal conditional message.
Evidence: Check an empty list, add a note, delete the last note, and refresh. Record actual results.
Secrets: No accounts or external APIs are needed for this exercise. Do not add them.
Recovery: Preserve unrelated work. Record a known-good commit before implementation.
Handoff: Update the roadmap with checks completed and anything still unverified.
